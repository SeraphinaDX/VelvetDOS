# VelvetDOS 0.11.0 EXEC allocator hotfix

On the normal FAT12 executable launch path, `reserve_exec_block` splits the
free conventional-memory MCB and saves `ES` one extra time without restoring
it. Its return instruction then reads the saved `BX` as an instruction pointer
instead of returning to the DOS `EXEC` handler. Symptoms can include restarts,
startup banners appearing again, freezing or other unpredictable control flow.

This hotfix removes the stray stack push and adds an offline assertion covering
the allocator split path. **The hotfix is not 86Box runtime verified.** It does
not change the filesystem format, boot sector or DOS interfaces.

Boot a fresh writable floppy image, then try `VER`, `HELP`, `DIR`, `HELLO`,
`HELLO` again, `MEMOWN` twice, `EXECHK hello MiXeD`, `HNDTEST`, `FINDTEST`.
If even built-in commands trigger a reboot, capture the exact sequence and
prompt/banner text; the allocator split path would not normally explain
built-in command failures.
